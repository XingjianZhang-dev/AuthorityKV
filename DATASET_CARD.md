# Dataset card: IH-CacheBench and external evaluation derivatives

## Purpose

IH-CacheBench tests a precise counterfactual: whether prompt-KV compression
changes an instruction-hierarchy decision that the same model makes correctly
under FullKV. It is intended for cache-compression diagnosis and
authority-aware retention research. It is not a generic jailbreak leaderboard,
an alignment score, or a production-security certification.

## Primary controlled benchmark

The primary split contains 400 conflict examples and 100 benign
controls. Conflict examples are balanced over five authority relations:

1. system versus user;
2. developer versus user;
3. system versus tool;
4. developer versus retrieved document; and
5. multi-tier conflicts.

Governing spans are balanced between prefix and mid-context positions.
Two smaller files follow the same design: a 120-example split (100 conflicts
and 20 benign controls) used for the no-prefix replication and the budget
curve, and a 30-example stratified subset used for the systems measurements.
Every conflict record contains exactly one governing decision, one
lower-authority decision, and one synthetic canary. Benign controls preserve
the response schema and length regime without an incompatible instruction.

All seven files under `data/ih_cachebench/` are generated by
`scripts/make_ih_cachebench.py` and `scripts/make_stratified_subset.py` from
fixed seeds. `bash scripts/build_ih_cachebench.sh` regenerates them and checks
that each is byte-identical to the released file.

## Record schema

Each JSONL record contains:

- a stable example identifier and category;
- typed chat messages or a serialized prompt;
- authority and provenance spans;
- the governing and subordinate source relation;
- an expected compact decision;
- an exact deterministic judge rule; and
- construction metadata.

Answers, canaries, grader arguments, and post-generation outcomes are not
provided to the cache selector. Dataset audits verify unique span markers,
tokenizer reconstruction, in-bounds offsets, disjoint protected/demoted token
sets, complete fields, and duplicate-free identifiers.

## External evaluation derivatives

### System-IFEval

The study fixes 150 prompts from 539 upstream System-IFEval prompts,
balancing the nine instruction families represented by the official grader
before generation. The original source key and commit are retained. The
official deterministic IFEval grader is used unchanged for prompt-strict and
instruction-strict evaluation.

### Mixed useful evidence and attack text

The study selects the lexicographically first 50 eligible LongBench TriviaQA
identifiers and 50 2WikiMultiHopQA identifiers before generation. Each source
pair is rendered in clean, explicit-injection, and paraphrased-injection
conditions. The insertion point is fixed immediately before the question and
does not depend on the answer. Reference answers and attack-marker labels are
stored separately from model-visible messages.

### IH-Challenge and capability checks

The release also keeps an adapted 40-item IH-Challenge evaluation and a
24-item RULER set converted from the official generator. Every comparison is
gated on the uncompressed model: where a model does not solve a task with its
full cache, the records are kept and no compression effect is reported for
that task.

## Evaluation and validation

No headline endpoint uses an LLM judge.

- IH-CacheBench uses exact decision and synthetic-canary matching.
- System-IFEval uses the released deterministic grader.
- LongBench answer utility uses the official task-normalized score.
- Attack success uses an exact per-example synthetic marker.

Unit tests cover judging edge cases. Stored text and token IDs are rejudged
during reconstruction, and manuscript numerators are regenerated from fixed
machine-readable summaries rather than copied from prose.

## Populations and exclusions

Compression comparisons admit only examples solved by the same model under
FullKV. The primary controlled split admits all 400 conflicts and 100 controls
for each of three models. External denominators, exclusions, capability gates,
runtime errors, and zero-effect cells are reported explicitly. Admission is
not evidence that a model is generally aligned; it establishes local
pre-intervention capability for the paired causal contrast.

## Personal and sensitive information

IH-CacheBench is programmatically generated and contains no recruited
participants, private conversations, credentials, or personal identifiers.
Synthetic canaries are non-secret strings. Reused public benchmark text
retains its upstream documentation and may contain ordinary public names or
topics inherited from those sources.

## Scope

- The controlled split is programmatically generated, which fixes the
  position, authority relation, and wording of every conflict and makes each
  decision exactly judgeable.
- Authority follows the roles and provenance that the orchestrator declares
  for each message and span.
- IH-CacheBench is evaluated on Qwen2.5-7B, Mistral-7B, Yi-1.5-9B, and
  Qwen2.5-14B. The external suites are run on Qwen2.5-7B, with System-IFEval
  repeated on Qwen2.5-14B and the mixed-evidence task on Mistral-7B.
- The tasks are in English, apart from the language-following requirements
  inherited from IFEval.
- Attack strings are fixed in advance, so every compressor is evaluated on
  the same inputs.
